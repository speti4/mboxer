# Tasks

One file per item, the folder is the stage: `backlog/` (open, not started — `status: idea | ready | blocked |
waiting`), `wip/` (in flight), `done/` (closed, never rewritten), `dropped/` (closed without work; keeps its id,
carries `reason` + `reopen-when`), `decisions/` (`D-NNN`, `proposed → decided → superseded`). Ids come from one
repo-wide counter, assigned at intake and never reused; a file keeps its name through every `git mv`. A backlog
item is frontmatter plus 2–10 lines (what, why, done-when) — anything longer is a plan of its own, not a longer entry.
Closing a task files every follow-up as a `backlog/` item now or deletes it with a reason. Driven by `/tasks`
(the maintainer's project-pal plugin); the section below is generated by `/tasks check` — edit the files, never
the section. Every file here is mirrored one-way into a GitHub issue by `scripts/sync-issues.py` (CI, on push) —
edit the file, never the issue. Everything here is English.
