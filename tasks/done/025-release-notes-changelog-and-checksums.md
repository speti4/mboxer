# 025 — Release notes and changelog from the task files, checksums and third-party licences

## Context

What: `CHANGELOG.md` generated per release from the `done/` task files (their H1 and milestone), by a mode of
`scripts/sync-issues.py` or a sibling script reading the same frontmatter, with the 0.1.0 section backfilled; the
release job takes its notes from it instead of `generate_release_notes`; a `SHA256SUMS.txt` next to the zip;
a `THIRD-PARTY-LICENSES.html` inside the zip generated by `cargo-about`.
Why: the v0.1.0 notes were written by hand because the generated ones were a bare "Full Changelog" line (no PRs);
the task files already hold the history, and the MIT / Apache crates inside the one exe require their notices.
Done when: a dry run of the release script (or a throwaway `-rc` tag, deleted afterwards) produces the notes,
the checksum file and the licence file.
Run as a task session under docs/git-workflow.md, in parallel with 035 and 032; no tag is pushed without the user.

## Build-time tools

- `cargo-about` 0.9.2 (D-002): build-time only, never linked into the exe — it renders the third-party licence page
  of the zip from the same Cargo.lock graph `cargo deny` checks, with the licence texts the crates ship; a
  hand-written collector would re-implement its licence-file discovery. Its own licence is `MIT OR Apache-2.0`,
  both on the D-011 allowlist (D-011 governs the shipped graph; the tool is outside it either way). Installed with
  `cargo install cargo-about --version 0.9.2 --locked --features cli` (released 2026-08-18; without `cli` the
  binary is not built).

## Deviations from the plan

- Changelog sibling script, not a mode of `sync-issues.py`: it runs offline in the release job (no `gh`, no
  issue token), writes a file instead of syncing issues; it loads the frontmatter reader and the roadmap from
  `sync-issues.py` via importlib, so there is one parser.
- Release membership by the tag trees (`git ls-tree v<version> tasks/done/`), not by the `closed` date: on
  2026-10-18 017 closed before the v0.1.0 tag and 021–034 after it, the same date.
- Entries link to the task file, not to the issue: issue N is not task N for every id (#34 is D-004).
- The notes travel as a file: `release.ps1` writes `dist/release-notes-<version>.md` (so the local dry run shows
  them too) and the job passes it to `gh release create --notes-file` instead of `--generate-notes`.
- Extra: the `deny` job compares `about.toml`'s accepted licences with `deny.toml`'s allowlist, so a mismatch
  fails at review time, not on the tag.
